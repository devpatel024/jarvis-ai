## Recommendation and plan conflict

**First benchmark whisper.cpp tiny.en and Vosk small-en-us against the same English recordings; start with eSpeak NG for TTS if GPL use is approved.** Compare base.en only if tiny accuracy is insufficient or as an explicitly approved second Whisper model. Do not select final STT until accent/noise accuracy and real-time factor are measured. Piper is a later natural-voice comparison option after separate engine/voice/transitive approval.

PLAN says not to run text and speech models concurrently. Sentence-by-sentence neural Piper TTS while Ollama continues generating conflicts with that policy. eSpeak's formant synthesis adds no neural speech model, so it can deliver early sentence playback without this conflict. Alternatively Piper needs an explicit policy exception or serial/pause scheduling; do not silently change PLAN. Native-library versus helper-process deployment and GPL compliance must be reviewed before redistribution, especially while the project licence is undecided.

Keep only one heavy Ollama model resident; the daemon may stay running. STT inference runs while text generation is stopped, release STT buffers/model before text generation, and use lightweight VAD/audio capture. If RAM headroom is low, unload the resident LLM before STT. Additive *planning estimates*, using observed 1b RSS (~1.40 GiB) plus upstream STT memory, are roughly tiny 1.65 GiB, base 1.76 GiB, Vosk 1.68 GiB; they exclude app/OS/audio and are **not measured joint peaks**. With 3b (~2.22 GiB) headroom worsens. No simultaneous neural STT + LLM computation, indexing, GPU or hidden background engine.

On this laptop, existing English 1b TTFT is 1.34 s warm / 12.75 s cold and generation ~3.34 tokens/sec. An illustrative 8–12-token first sentence adds about 2.4–3.6 seconds of decoding, plus STT and synthesis/playback buffering; this is an arithmetic planning example, **not a voice latency measurement**. Unloading/reloading the LLM can make each conversation turn cold. Developer metrics must expose this instead of claiming instant conversation.

## Step 2 design, after approval only

Existing streaming LlmProvider stays unchanged. Domain contracts SpeechToText, TextToSpeech, AudioInput, VoiceActivityDetector and VoiceSessionController have fake implementations for tests and Riverpod composition. State machine: idle → listening → transcribing → thinking → speaking; thinking/speaking can describe streaming/pending sentences with explicit playback state. Errors/cancellation must clean all buffers/playback/jobs and leave mic off.

Push-to-talk holds Space/mic, release or bounded VAD ends the utterance. Conversation mode explicitly starts listening, then re-listens after playback, exits on silence timeout or recognized stop/goodbye. Space/mic tap during playback cancels synthesis/playback before listening. Ignore mic during playback to prevent self-answering; no wake-word listener. Use in-memory PCM/C API input, not a temp audio file. AudioInput/plugin/native device bindings remain unselected and require a separate pinned dependency/native audit before adoption.

Listening orb follows measured mic level; STT/LLM thinking, actual playback speaking. Live transcript/listening indicator, visible active mic, contextual permissions, Android RECORD_AUDIO explanation, Settings voice disable and privacy-first default. OS/app reduce motion still applies; drop to Lite during STT. Gujarati voice remains disabled with experimental/limited-accuracy and unverified labels, English-only model paths; poor Gujarati LLM results are not measurements of STT/TTS accuracy. Phase 5 owns later real Gujarati samples. Wake-word interface/disabled explanatory setting only.

Measurements after approval: real English samples with varied accent/noise, manual transcript/WER, duration, STT RTF (compute seconds / audio seconds), STT end-of-utterance latency, TTS request-to-first-played-audio, utterance-end to first Jarvis audio and full turn, stage RSS peaks (app/helper/Ollama reported separately), model load state and CPU thread count. No raw audio saved by default; test fixture recording/storage requires explicit consent. Compare tiny/base/Vosk one at a time; do not assume RTF <1 on the i5. Verify sentence queuing, cancellation, buffer bounds, microphone permissions, speakers/headphones and echo suppression.

Required tests after implementation: fakes for all transitions/error cleanup/barge-in/silence timeout/late events, widget voice states/accessibility and privacy switch, format/analyze/tests/Linux release build, offline operation, actual mic/speaker/headphone manual checks. **Voice latencies, RAM per voice stage, microphone and playback tests: NOT RUN**, because Step 1 intentionally stops before downloads/integration.
